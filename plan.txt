OLX Monitor v2 – Plan Architektoniczny (Wersja Finalna)
Context
Obecna architektura ma krytyczne błędy strukturalne: mediana liczona niezależnie w 3 miejscach, stale deal.marketMedian, luźna kategoryzacja (2GB iPhone w grupie iPhone 17), minPrice użytkownika zmienia dataset OLX, brak walidacji logicznej, dashboard oblicza własne dane zamiast korzystać z backendu.

Cel v2: jeden pipeline normalizacji → jedna klasa eligibility → jedno źródło statystyk (MarketSnapshot). Wszystkie sekcje systemu korzystają z identycznych danych. Dashboard nie oblicza nic po swojemu.

ZASADY ARCHITEKTONICZNE (STABLE CORE)
Poniższe reguły są nienaruszalnymi kontraktami systemu:

minPrice użytkownika NIGDY nie trafia do budowy mediany rynku. minPrice = filtr UI.
Wszystkie sekcje korzystają z jednego MarketSnapshot – nie liczą median samodzielnie.
configKey opisuje wyłącznie konfigurację sprzętową. Condition NIE jest częścią configKey.
Klucz snapshotu = ${configKey}:${condition} – jedyny format, wszędzie identyczny.
Backend jest jedynym arbitrem configKey i statystyk rynku. Dashboard nic nie oblicza.
Każdy listing ma jednoznaczną eligibility: market_eligible, visible_only lub rejected.
Tylko market_eligible buduje medianę i może generować deale/powiadomienia.
AI/analyzer NIE wpływa na configKey, klasyfikację wariantu, medianę ani snapshoty.
monitorRules jest jedynym źródłem reguł monitoringu w runtime.
Scheduler resolved monitora używa buildSearchQuery(configKey), nie raw query użytkownika.
Snapshoty są zawsze kluczowane przez configKey:condition, nie przez arbitralne query.
cheapestVisible (visible_only) NIE jest danymi rynkowymi – nie może być używany do: liczenia okazji, wyliczania % od mediany, CTA "świetna okazja" ani do "najtańszych ofert rynkowych".

  | 'market_eligible'   // buduje medianę; może generować deale i powiadomienia
  | 'visible_only'      // widoczne pomocniczo w UI; NIE buduje mediany; NIE generuje deali

Zasady klasyfikacji rejected – gdy GŁÓWNYM przedmiotem oferty jest:

Akcesorium (etui, case, folia, kabel, ładowarka, szkło ochronne) – rozpoznawane po: tytule zaczynającym się od nazwy akcesorium LUB kategorii OLX = "Akcesoria/Etui/Kable"
Usługa / naprawa / serwis
„Na części", „nie działa", „uszkodzone" (główny przedmiot = uszkodzony sprzęt)
Ogłoszenie niemające związku z urządzeniem
Model fizycznie niemożliwy
Reguła device+bonus: Listing „iPhone 17 256GB + etui gratis" NIE jest rejected. Gdy akcesorium to DODATEK (słowa: „gratis", „w zestawie", „w komplecie", „w pudełku"), a głównym produktem jest urządzenie → listing dostaje flagę accessory_bonus i przechodzi pełną walidację jak każdy inny listing. Jego końcowa eligibility może być market_eligible albo visible_only zależnie od pozostałych reguł (confidence, requiredForConfigKey etc.). Flaga accessory_bonus jest WYŁĄCZNIE informacyjna – nie ratuje listingu do market_eligible ani nie obniża confidence.

Zasady klasyfikacji visible_only – urządzenie poprawne, ale niewystarczające do mediany:

parsingConfidence < 0.6
Brak któregokolwiek pola z requiredForConfigKey adaptera
Bundle (kilka urządzeń razem)
Cena = 0 lub brak ceny
Parametry OLX sprzeczne z tytułem
Brak adaptera (nieznana kategoria produktu) – trafia do visible_only, nie do żadnej grupy
variant_ambiguous flag + adapter zdecydował, że niepewność wyklucza market_eligible
market_eligible – pełne uczestnictwo:

confidence ≥ 0.6, wszystkie requiredForConfigKey wypełnione, brak hard_reject flag

// Dwa różne powody braku wariantu – muszą być rozróżnione:
export type VariantCertainty =
  | 'confirmed'    // wariant wykryty jednoznacznie (pro max, pro, air, plus, mini)
  | 'base_model'   // brak wariantu = to faktycznie model bazowy (tytuł nie zawiera żadnego wariantu)

Reguła:

variant_certainty = 'base_model' + variant = undefined → listing może być market_eligible dla configKey bez wariantu (np. apple_iphone_17_256gb)
variant_certainty = 'ambiguous' + variant = undefined → listing jest visible_only (nie buduje żadnej grupy, bo nie wiadomo jakiego modelu dotyczy)
max bez pro → variant_certainty = 'ambiguous', confidence -= 0.25, flags.push('variant_ambiguous')

Kanoniczna sygnatura (finalna – zgodna z F2 + F7):


// KROK 1–6 używa fields (z AdapterNormalizationResult), penalties, adapter, isBundle
export function validateNormalized(
  fields: Partial<NormalizedListing>,
  penalties: { flag: string; delta: number }[],
  input: AdapterInput,
  adapter: BaseAdapter,
  isBundle: boolean,       // przekazywane jawnie z normalizeListing(), nie z partial
): ValidationResult {
  // KROK 1: Hard reject (title + description + olxCategory)
  if (isMainProductAccessory(input)) return reject('accessory');
  if (isServiceListing(input))       return reject('service');
  if (isDamagedForParts(input))      return reject('parts_only');
  if (isImpossibleModel(fields))     return reject('impossible_model');

  // KROK 2: Confidence + flags z penalties adaptera
  let confidence = 1.0;
  const flags: string[] = [];
  for (const p of penalties) { confidence += p.delta; flags.push(p.flag); }
  // accessory_bonus: jeśli w penalties → dodaj do flags informacyjnie, NIE obniża confidence

  // KROK 3: requiredForConfigKey
  const missing = adapter.requiredForConfigKey.filter(f => !fields[f as keyof NormalizedListing]);
  if (missing.length > 0) {
    flags.push('incomplete_config');
    return { eligibility: 'visible_only', confidence, flags };
  }

  // KROK 4: VariantCertainty
  if (fields.variantCertainty === 'ambiguous') {
    return { eligibility: 'visible_only', confidence, flags: [...flags, 'variant_ambiguous'] };
  }

  // KROK 5: Bundle (jawne przekazanie, nie z partial)
  if (isBundle) return { eligibility: 'visible_only', confidence, flags: [...flags, 'bundle'] };

  // KROK 6: Confidence threshold
  if (confidence < 0.6) return { eligibility: 'visible_only', confidence, flags };

  return { eligibility: 'market_eligible', confidence, flags };
}

Etap 3 – Normalizer Pipeline (src/normalizer/index.ts)

// STABLE CORE – single normalization pipeline
export function normalizeListing(raw: OlxRawListing): NormalizedListing {
  const input: AdapterInput = {
    title: raw.title, description: raw.description,
    olxParams: raw.params, olxCategory: raw.category, price: raw.price,
  };

  // isAccessory i isBundle: title + description + olxCategory (nie tylko title)
  if (isMainProductAccessory(input)) {
    return { ...rawToBase(raw), eligibility: 'rejected', isAccessory: true, isBundle: false,
      parsingConfidence: 0, validationFlags: ['accessory'], configKey: undefined, condition: 'unknown' };
  }

  const adapter = ADAPTERS.find(a => a.canHandle(input)) ?? null;
  if (!adapter) {
    // Nieznana kategoria → visible_only, NIE wyświetlana jako wariant w Rynku
    return { ...rawToBase(raw), eligibility: 'visible_only', isAccessory: false,
      isBundle: detectBundle(input), parsingConfidence: 0.1,
      validationFlags: ['no_adapter'], configKey: undefined, condition: determineCondition(input) };
  }

  // Finalny flow zgodny z F2 + F7:
  const { fields, penalties } = adapter.normalize(input);  // AdapterNormalizationResult
  const isBundle = detectBundle(input);                    // PRZED validateNormalized
  const { eligibility, confidence, flags } = validateNormalized(fields, penalties, input, adapter, isBundle);
  const configKey = (eligibility !== 'rejected') ? adapter.buildConfigKey(fields) : undefined;

  return {
    ...rawToBase(raw), ...fields, configKey,
    parsingConfidence: confidence, eligibility,
    isAccessory: false, isBundle,
    validationFlags: flags, condition: determineCondition(input),
    // REGUŁA: adaptery NIE ustawiają condition – zawsze nadpisywane przez determineCondition(input)
    // isSuspiciousPrice: BRAK tutaj – uzupełniane przez market-scanner po obliczeniu mediany
  };
}

export async function handlePriceAnalysis(query: string, condition: string, _minPrice = 0) {
  // NIE używa minPrice – NIGDY
  const { snapshots } = await computeSnapshot(query, condition);
  if (!snapshots.length) return ok({ variants: [], message: 'Nie znaleziono wariantów' });

  if (snapshots.length === 1) {
    // Jeden wariant – zawsze zwróć z dataConfidence (nie udawaj pełnej pewności gdy low)
    return ok({ variant: formatVariant(snapshots[0]!), variants: null,
      requiresSelection: false, dataConfidence: snapshots[0]!.dataConfidence });
  }
  // Wiele wariantów → UI musi poprosić o wybór; NIE auto-selekcja
  return ok({ variant: null, variants: snapshots.map(formatVariant),
    requiresSelection: true, message: `Znaleziono ${snapshots.length} wariantów. Wybierz.` });
}
5C. handleGetDeals()

export function handleGetDeals(): HandlerResult {
  const itemsList = loadItems();
  const deals = loadDeals().sort(byFoundAtDesc).map(deal => {
    if (!deal.configKey) return { ...deal, liveDataConfidence: 'no_data' };
    const condition = itemsList.find(i => i.id === deal.itemId)?.condition ?? 'all';
    const snap = getSnapshot(deal.configKey, condition);
    if (!snap) return { ...deal, liveMarketMedian: undefined, liveDataConfidence: 'no_data' };
    const discount = (snap.stats.median - deal.listing.price) / snap.stats.median;
    return { ...deal,
      liveMarketMedian: snap.stats.median,
      liveDiscount: Math.round(discount * 100),
      liveQuality: classifyDiscount(discount),
      liveDataConfidence: snap.dataConfidence,
      // low/no_data → UI pokazuje wyraźne ostrzeżenie w karcie deala
    };
  });
  return ok(deals);
}

Etap 6 – deal-detector.ts

// TYLKO dla market_eligible listingów
// visible_only i rejected NIE trafiają tutaj – hard guard
export async function scoreDealFromNormalized(listing: NormalizedListing, condition: string): Promise<DealScore> {
  if (listing.eligibility !== 'market_eligible') return noScore(listing);
  // Reguła condition matching (STABLE – kanoniczna implementacja z F6):
  const lc = listing.condition;
  const mc = condition;
  const conditionCompatible =
    (lc === 'new'     && (mc === 'new'  || mc === 'all')) ||
    (lc === 'used'    && (mc === 'used' || mc === 'all')) ||
    (lc === 'unknown' &&  mc === 'all');  // unknown → TYLKO all
  if (!conditionCompatible) return noScore(listing);
  if (!listing.configKey) return noScore(listing);
  const snap = getSnapshot(listing.configKey, condition);
  if (!snap || snap.stats.median <= 0) return noScore(listing);
  const discount = (snap.stats.median - listing.price) / snap.stats.median;
  return { isNoScore: false, configKey: listing.configKey, marketMedian: snap.stats.median,
    discount: Math.round(discount * 100), quality: classifyDiscount(discount),
    p25: snap.stats.p25, p75: snap.stats.p75 };
}

async function checkItem(item: MonitoredItem): Promise<void> {
  const rawListings = await scrapeListings(item);
  const normalized = rawListings.map(normalizeListing);

  // ONLY market_eligible generuje deale – visible_only i rejected ignorowane
  const candidates = normalized.filter(l => l.eligibility === 'market_eligible');

  for (const listing of candidates) {
    if (dealExistsForListing(listing.id)) continue;
    const score = await scoreDealFromNormalized(listing, item.condition);
    // hasValidScore (zgodnie z F5): discount może być 0 lub ujemny – to nadal valid score
    const hasValidScore = !score.isNoScore && score.marketMedian > 0;

    // monitorRules: jedyne źródło reguł
    const rules = item.monitorRules;
    // budgetMode nie wymaga score – działa wyłącznie na cenie
    const passesBudget = rules.budgetMode ? listing.price <= rules.budgetMode.maxPrice : false;
    // marketMode WYMAGA valid score – bez snapshotu nie można ocenić okazji rynkowej
    const passesMarket = hasValidScore && rules.marketMode
      ? score.discount >= rules.marketMode.minDiscountPct
      : false;

    // triggerLogic ma znaczenie tylko gdy oba tryby aktywne jednocześnie
    let passes: boolean;
    if (rules.budgetMode && rules.marketMode) {
      passes = rules.triggerLogic === 'all' ? (passesMarket && passesBudget) : (passesMarket || passesBudget);
    } else {
      passes = passesMarket || passesBudget;
    }
    // monitor tylko marketMode + brak snapshotu → passes=false → listing pominięty
    // monitor tylko budgetMode + brak snapshotu → passes=passesBudget (score nieistotny)
    if (!passes) continue;

    const analysis = await analyzeListing(listing, score);
    const deal = buildDeal(listing, score, analysis, item.id);
    deal.marketMedianAtDiscovery = score.marketMedian;
    upsertDeal(deal); notify(deal, item);
  }
}

// Refresh snapshotów – priorytetowy, nie blokuje
async function refreshSnapshots(): Promise<void> {
  const activeItems = loadItems().filter(i => i.enabled);
  for (const item of activeItems) {
    if (item.monitorStatus === 'resolved' && item.configKey) {
      // Resolved: używaj dedykowanego snapshotu po configKey
      const snap = getSnapshot(item.configKey, item.condition);
      if (!snap || isStale(snap) || snap.dataConfidence === 'low') {
        const variant = buildVariantFromItem(item);
        await computeVariantSnapshot(variant, item.condition); // targeted, nie broad
      }
    } else {
      // Unresolved/legacy: broad scan by searchQuery, próba auto-resolve
      // Snapshoty z tego toku: kluczowane po configKey:condition (nie po query)
      const result = await discoverAndBuildSnapshots(item.searchQuery, item.condition);
      // Jeśli znaleziono JEDEN wariant z high confidence → auto-propose resolved upgrade
      // (nie auto-upgrade; wymaga potwierdzenia przez UI lub API call)
      if (result.snapshots.length === 1 && result.snapshots[0]!.dataConfidence === 'high') {
        item.suggestedConfigKey = result.snapshots[0]!.configKey;   // pole informacyjne
        item.suggestedConfigKeyLabel = result.snapshots[0]!.label;  // human-readable label dla UI
        upsertItem(item); // zapisz sugestię dla UI
      }
    }
  }
}
